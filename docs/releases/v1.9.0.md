# RoyalDownloader v1.9.0

Stable v1.9.0 promotes the verified improvements accumulated since v1.8.0
on both main and overnight. It focuses on reliable German-language downloads,
more useful discovery and personal Jellyfin lists, and clearer, safer updates.

## Highlights

- **People discovery and filmographies.** Explore TMDB people with portraits,
  biographies, known works, movies and TV credits, and practical filters.
  Open cast filmographies from title details and select checked films for
  batch downloads using existing library and source safeguards.
- **Personal Jellyfin watchlist.** Use "+ Merken" on movies and series to save
  requests per Royal profile. Available media are synchronized into private
  playlists for linked Jellyfin users; unavailable titles remain pending.
  Saving a title does not trigger a download.
- **German audio means German audio.** Hoster titles containing GerSub and
  other German-subtitle-only evidence are not accepted as proof of German
  dubbing. Explicit, verified audio tracks take precedence. Episode checks,
  queue requests and subscriptions retain the selected language contract.
- **AniWorld fallback for series episodes.** Enabled AniWorld sources can
  complement normal series providers when matching exact titles or aliases,
  release years, native season/episode numbering and the requested audio.
  The original download identity and destination are preserved.
- **Faster, more informative availability.** Movie details share bounded
  source checks, show successful results progressively, and retry inconclusive
  answers without treating temporary provider problems as permanent absence.
  Watchlist state is preserved while availability updates.
- **Safer, more transparent updates.** The updater keeps strong CI/signature
  checks and restart/rollback verification, rejects stale approvals, and shows
  GitHub links comparing the installed and offered revisions plus a pinned
  changelog before an update is installed.
- **Maintenance and mobile improvements.** Dependabot minor/patch updates are
  grouped per ecosystem for a weekly Monday schedule. Mobile movie and series
  watchlist buttons are better aligned, with clearer independent feedback.

## Compatibility

This release keeps existing Royal accounts, profiles, sessions, subscriptions,
download queues, source/language preferences, Jellyfin integrations, media
destinations and persistent storage. Existing HTTP, `/api/v1`, WebSocket and
Docker deployment conventions remain compatible. No new mandatory environment
variables or forced proxy settings are introduced.

As always, verify integrations and permissions against your actual NAS after
updating; third-party provider behavior can change independently.

## Upgrade

Back up at least `.env`, `data/` and `runtime/` before upgrading, including
a rollback copy of the running source revision. In **Settings → Updates and
Wartung**, choose the **Stable** channel and review the linked changelog and
commit comparison before installing. Existing Overnight installations should
check the branch-switch warning before moving to Stable.

For a pinned source deployment after publication:

```bash
git fetch --tags origin
git switch --detach v1.9.0
APP_COMMIT_SHA="$(git rev-parse HEAD)" docker compose up -d --build
curl --fail http://127.0.0.1:8765/api/health
```

After startup confirm version `1.9.0`, queue and subscription state, language
selection, Jellyfin mappings, media mounts and read/write permissions. See the
[release operations guide](../RELEASE.md) for fresh installs and full upgrade
instructions.

## Rollback

If a rollout fails, use the existing versioned runtime rollback flow to
activate the previous complete release; alternatively restore a backed-up
source tag/commit and its compatible persistent state. Keep `data/` and
`runtime/` backups until the new version has been validated. See the
[rollback instructions](../RELEASE.md#rollback).

## Verification

The promotion into main passed its required protected-branch checks. The
version-bump pull request must pass the same `verify` gate. On merge, the
official [release workflow](../../.github/workflows/release.yml) repeats
Quality before creating the annotated `v1.9.0` tag and GitHub Release.
This includes Python/frontend regressions, dependency and security checks,
container validation and upgrade/restart/rollback fixtures.

## Known limitations

- External media sources, hosters, GitHub and TMDB can be temporarily
  unavailable; neither the download service nor upstream language metadata
  guarantees future availability.
- A matching subtitle release does not guarantee requested spoken audio;
  downloads may remain pending if no provider can verify that audio.
- A pinned GitHub commit comparison needs identifiable installed and target
  revisions. The project's editorial changelog describes releases and may not
  enumerate every intermediate Overnight commit.
- The optional privacy proxy does not guarantee anonymity.
