# RoyalDownloader v1.5.0

Stable v1.5.0 promotes the fully tested RoyalDownloader state from 1 October
2026. It includes the household-profile, storage, series-catalog, homepage and
settings work completed after v1.4.0.

## Highlights

- **Household switching is smoother and clearer.** Profile names and login names
  are separate, first-time profiles can create their password directly from
  **Wer schaut gerade?**, and a successful protected switch is remembered for
  the current browser session.
- **Storage destinations are easier to understand.** Standard movie/series
  targets are shown explicitly, additional locations can be restricted to
  movies, series and/or anime, and Storage Autopilot keeps those choices during
  automatic placement.
- **Series browsing now matches the movie experience.** Jellyfin badges
  synchronize across duplicate card instances, paging is bounded to normal
  batches and infinite scroll recovers after temporary cold-start responses.
- **Home discovery is more varied.** Current cinema releases receive stronger
  hero priority, deeper discovery pages rotate into the candidate pool and
  taste/exposure data reduce repetitive recommendations.
- **Explore artwork is consistently cinematic.** “Heute mal etwas anderes”
  publishes only ready 16:9 backdrops, never portrait poster fallbacks or
  initials placeholders.
- **Settings received a full responsive redesign** without changing the
  underlying configuration contracts.

## Quality and security

The Stable promotion is protected by RoyalDownloader's complete quality
workflow, including Chromium and WebKit browser regressions, mobile interaction
checks, frontend performance budgets, Python and JavaScript tests, dependency
audits, security scans, container build and vulnerability scanning, end-to-end
first-run/auth/queue/provider flows, and upgrade/rollback verification.

The promoted main state immediately before this release passed 1,174 Python
tests as well as all browser, security, container and E2E gates.

## Compatibility

This release is additive. Existing accounts, household profiles, Jellyfin
mappings, sessions, queues, subscriptions, media paths, provider configuration,
Storage Autopilot policy and taste profiles remain compatible.

Existing additional storage locations keep their prior behavior until their
media-type choices are explicitly changed. Standard movie and series targets
remain valid fallback/start destinations.

## Upgrade

Back up at least `.env`, `data/` and `runtime/`, then update to `v1.5.0` through
the normal Stable updater or a pinned checkout. After startup:

1. verify **Settings → Updates and maintenance** reports v1.5.0;
2. open **Wer schaut gerade?** and confirm profile switching behaves as expected;
3. review **Storage** to confirm standard targets and additional media-location
   permissions;
4. browse Movies and Series far enough to verify pagination and Jellyfin badges.

## Rollback

Use the normal Stable rollback flow. Royal keeps the previous versioned runtime
available when the standard update path is used. Preserve the pre-upgrade
persistent-data backup until the updated installation has passed its health and
library checks.

## Known limitations

- External providers and hosters may change or become unavailable independently
  of RoyalDownloader.
- Current cinema and recommendation freshness depend on reachable metadata
  sources.
- Profile avatars remain RoyalDownloader presentation assets and are not
  synchronized back to Jellyfin user artwork.
- Automatic storage actions remain deliberately conservative and can be blocked
  by ownership, capacity, active-queue, playback or mount-safety checks.
