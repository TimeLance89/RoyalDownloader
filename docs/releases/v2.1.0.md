# RoyalDownloader v2.1.0

## The media-center release

**Discover. Download. Press play.** RoyalDownloader v2.1.0 brings direct browser
playback into the same interface as discovery, downloads and your personal
library. An available film or episode can now be watched directly in Royal,
powered by your existing Jellyfin server.

This is a substantial product expansion. Download management, subscriptions,
language checks, personal recommendations and storage automation remain part
of Royal; the new player connects them to the viewing experience.

## Highlights

- **Integrated film and episode player.** Open available Jellyfin content from
  its detail view. The player identifies the film or the series, season and
  episode, with a timeline, elapsed and total time, 10-second skips, volume,
  playback speed and keyboard controls.
- **Fullscreen and picture-in-picture.** A dedicated fullscreen presentation
  keeps the video central and reveals controls on pointer or keyboard activity.
  Picture-in-picture is offered where supported by the browser.
- **Personal Continue watching.** Home shows resumable films and episodes with
  their saved times. Detail play buttons offer the saved position as well.
  Open details, hide an entry, mark it watched or undo a recent supported action.
- **Seasons and episodes in Royal.** Series details show your available Jellyfin
  episodes and progress alongside the download view. The player adds previous/
  next episode navigation and an episode menu with season selection.
- **Playback for the household.** Enabled members and administrators can watch
  through their linked Jellyfin profiles. Stream resources and progress are
  checked against the current session, profile and visible item. Account or
  connection changes invalidate old playback contexts.
- **Jellyfin-negotiated streaming.** Direct play or HLS uses a server-prepared
  playback session, private same-origin resources and a consistent timeline for
  seeking. Server credentials stay on the Royal server.
- **Existing Intro/Outro metadata.** An authenticated backend API reads available
  Jellyfin media segments. Detection stays in Jellyfin or its configured tools;
  this release does not add intro-skip controls to the web player.
- **Reliable storage confirmation.** Unchanged status polling keeps the pressed
  Mount confirmation button in place, preventing a lost click during refresh.
- **Documentation rebuilt around the media center.** The README now covers the
  full discover/download/watch workflow, personal playback and first-play setup,
  with a dedicated [media-center guide](../MEDIA_CENTER.md).

## Compatibility

Existing accounts, settings, download queues, subscriptions, personal lists,
media mounts and versioned runtime paths remain in use. The existing HTTP,
versioned API and WebSocket contracts remain available; new playback routes are
additive. Application capabilities now report `application_version: 2.1.0`.

Jellyfin browser playback requires a reachable configured server, a linked
Jellyfin profile for each Royal account and playback permission for the chosen
item. Use separate Jellyfin profiles for independent watched progress. Two Royal
accounts linked to the same Jellyfin profile share that profile's state.

The Plex integration retains its documented library/request scope. The new
in-app streaming player uses Jellyfin. No separate media-server container is
added, and Royal does not perform its own Intro/Outro analysis.

## Upgrade

Back up `.env`, `data/`, `runtime/` and the current source revision first. Keep
existing media mounts, credentials and household accounts. Drain or pause active
downloads and stop the stack before copying mutable data; see
[release operations](../RELEASE.md#backup-before-an-update).

For a version-pinned Docker source installation, after taking the backup:

```bash
docker compose down
git fetch --tags origin
git status --short
# Stop here if local source changes are listed. Preserve them before switching.
git switch --detach v2.1.0
docker compose config --quiet
APP_COMMIT_SHA="$(git rev-parse HEAD)" docker compose up -d --build
curl --fail http://127.0.0.1:8765/api/health
curl --fail http://127.0.0.1:8765/api/v1/capabilities
```

Versioned in-app Stable updates continue to use the existing verification and
rollback workflow. Keep existing image-level init/security protections; source
runtime updates do not install missing operating-system packages.

After updating:

1. Verify version **2.1.0**, your existing queue, subscriptions and media mounts.
2. Check the Jellyfin connection and each account's household profile mapping.
3. Start a film, seek, close it and resume from Continue watching.
4. Check episode navigation and season selection for an available series.
5. Confirm independent progress under two different linked Jellyfin profiles.

## Known limitations

- Playback and seeking depend on Jellyfin availability, server/transcoding
  capacity, browser codec support and the connection to the Royal server.
- Fullscreen and picture-in-picture depend on browser/platform support.
- A title's catalog ownership marker does not override the linked profile's
  permission to play that item. Unlinked or forbidden profiles cannot stream it.
- Existing segment metadata may be empty or unsupported on the Jellyfin server;
  the backend exposes that result without inventing markers or starting analysis.
- Removing a Continue watching card hides it in Royal; it does not delete the
  file or erase playback progress. New playback activity may make it appear again.
- Already delivered/buffered video cannot be recalled after a permission change.
  Subsequent resource requests are checked, and long streams periodically
  revalidate access. Details are in the media-center guide.

## Rollback

Use the existing guarded runtime rollback, or restore the known-good **v2.0.4**
source revision with its compatible backup. Preserve your media volumes and
integration/authentication keys. See [rollback operations](../RELEASE.md#rollback).
