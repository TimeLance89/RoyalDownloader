# RoyalDownloader v1.7.0

Stable v1.7.0 promotes the current Overnight work into the official Stable
channel. The focus is safer language handling, a clearer first-run experience,
and more reliable source selection for multilingual movies, series, anime and
subscriptions.

## Highlights

- **First-run setup is now guided and recoverable.** The onboarding flow uses
  the same language-studio design as the rest of Settings, walks through seven
  clear steps, separates interface and content language, and lets users review
  the complete profile before it is saved.
- **Language profiles are easier to understand.** Sources are presented with
  clear first-choice and fallback roles, language badges and expandable inactive
  providers instead of exposing a flat provider list.
- **Content language is now a hard download contract.** A job created for German
  can no longer silently continue with an English source merely because English
  is enabled elsewhere in the profile.
- **Multilingual episodes are verified before selection.** Concrete episode and
  hoster language evidence is shared across detail views, subscriptions and
  queued work so unchecked or wrong-language sources remain pending instead of
  being treated as valid.
- **Subscriptions keep their intended language.** Existing queued episodes are
  revalidated after upgrading, wrong-language sources wait for the requested
  language, and deferred checks remain visible without stale failure badges.
- **Anime language checks join normal source monitoring.** Untested episode
  tracks are scheduled for bounded checks and their availability is surfaced in
  Settings.
- **Provider capability and real stream evidence are separated.** FilmPalast,
  Huhu, KinoGer, KinoKing and SerienStream can advertise multilingual capability
  without that label being mistaken for proof that every concrete stream is
  German.
- **HLS/DASH audio routing stays strict when language metadata exists.** Muxed
  streams without reliable manifest tags still follow provider-level routing
  instead of inventing audio-language evidence.

## Reliability and upgrade behavior

The release also carries the accumulated Overnight hardening around provider
monitoring, source resolution, persistence, queue handling, catalog refresh,
update checks and frontend recovery. Existing persistent data formats remain
compatible.

The official release workflow runs RoyalDownloader's complete Quality workflow
before the tag and GitHub Release are created. That gate covers Python and
frontend regression suites, syntax and static checks, dependency/security
audits, container build/startup validation, browser regressions and the Stable
upgrade/rollback path.

## Compatibility

This is an additive minor release. Existing accounts, household profiles,
sessions, queues, subscriptions, Jellyfin mappings, provider preferences, media
paths, Storage Autopilot policy, personal requests and update-channel selection
remain compatible.

Existing content-language choices are preserved. When a saved subscription has a
language contract, v1.7.0 keeps that contract and revalidates unresolved or
legacy queued work instead of silently changing language.

## Upgrade

Back up at least `.env`, `data/` and `runtime/`, then update to `v1.7.0`
through the normal Stable updater or a pinned checkout.

After startup:

1. verify **Settings → Updates and maintenance** reports v1.7.0;
2. review **Settings → Sources** and the guided language/source profile;
3. open one multilingual series and confirm the expected episode language;
4. check existing subscriptions and queued episodes for the intended language;
5. confirm Jellyfin mappings, media paths and Storage Autopilot state are
   unchanged.

## Rollback

Use the normal Stable rollback flow. Royal keeps the previous complete runtime
release and the release gate verifies upgrade, restart, rollback and backup
recovery against published Stable data.

If rolling back to v1.6.0, keep the normal `data/` and `runtime/` backup
available. v1.6.0 does not contain the stricter v1.7.0 language-contract and
guided language-profile behavior, but the persistent state remains compatible.

## Known limitations

- Third-party providers, mirrors and hosters can change availability, domains,
  protection or page structure independently of RoyalDownloader.
- A multilingual provider label alone is intentionally not accepted as proof of
  a concrete episode's audio language; when evidence is unavailable, the item
  may remain pending instead of being guessed.
- Some HLS/DASH sources expose reliable audio-language metadata while muxed or
  opaque streams do not. Routing therefore uses the strongest evidence actually
  available for each source.
- Deferred or temporarily unavailable language checks can delay selection or
  subscription processing until a bounded recheck succeeds.
