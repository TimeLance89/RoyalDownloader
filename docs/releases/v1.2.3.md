# RoyalDownloader v1.2.3

## Series pagination recovery

The series catalog now retries temporary preparation, network and upstream
failures when appending a page. Attempts are limited to three within a total
30-second deadline, with short delays between attempts. Existing cards remain
mounted and the page cursor advances only after a successful response.

If a provider deadline leaves a follow-up page incomplete, the API reports
`series_catalog_pending` (HTTP 409) instead of returning a truncated page that
could skip titles. A genuinely complete final page can still be shorter.

After retries are exhausted, scrolling no longer repeatedly sends the same
failed request. **Erneut versuchen** retries that page explicitly. Leaving the
view cancels pending requests and backoff. Initial loading and search keep their
existing behavior.

## Regression coverage

Unit tests cover temporary and permanent errors, bounded attempts and lifecycle
cancellation. Backend tests cover incomplete pages and the retryable API
contract. Desktop and touch-mobile browser tests exercise automatic recovery,
manual recovery and retention of existing card nodes through the real interface.
These browser tests run in the regular quality workflow.

## Compatibility

No persistent format, deployment, CSS, image quality or carousel change is
included. All logical titles remain available. The existing v1.2.1 catalog and
v1.2.2 similar-detail fixes are preserved.

## Upgrade

Back up `.env`, `data/` and `runtime/`, then use the Stable updater or check out
`v1.2.3` and rebuild with the existing Compose mounts. Verify
`application_version: 1.2.3` in `/api/v1/capabilities`. Open Series and scroll past
the first page. See [release operations](https://github.com/TimeLance89/RoyalDownloader/blob/v1.2.3/docs/RELEASE.md).

## Rollback

Use runtime rollback or rebuild the recorded previous tag with unchanged
volumes. No data deletion or migration reversal is needed. Returning to v1.2.2
restores the former pagination failure handling.

## Known limitations

Provider outages can outlast the retry budget; a manual retry remains available.
The reported intermittent error was reproduced using controlled preparation and
upstream failures. No production HTTP trace was available to establish which
external failure triggered the original screenshot.
