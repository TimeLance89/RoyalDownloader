# RoyalDownloader v2.0.2

RoyalDownloader v2.0.2 brings the Overnight improvements since v2.0.1 to Stable:
subscription artwork, signed official announcements, clearer source-search
feedback and more reliable mandatory browser validation.

## Highlights

- **Subscribed-series posters.** The subscribed-series shelf follows the cinema
  catalog presentation, with small posters, readable titles and separate
  subscription rules and status. Existing artwork is loaded lazily, with proxy
  and initials fallbacks. Detail navigation and management actions are retained.
- **Signed announcements in the Abo-Inbox.** Official news supports per-profile
  read state, expiration, signed revocation and a verified offline cache. Local
  administrators can disable receipt in Settings. Global publishing is disabled
  on ordinary installations and requires the configured official owner and the
  matching private signing key on the official server.
- **Clearer movie source search.** Ongoing retries now say that further providers
  are being checked, rather than implying confirmed source unavailability.
  Search, polling, provider selection and timeout behavior are unchanged.
- **Clearer NAS configuration.** The environment example distinguishes container
  download paths from NAS host mounts, documents disabled publisher defaults and
  identifies ROYAL_BIND_ADDRESS as the replacement for deprecated BIND_ADDRESS.
- **Reliable browser gates.** The versioned Playwright container provides the
  matching browsers and OS libraries, avoiding repeated package downloads. The
  complete Chromium, performance and WebKit gates must actually pass; the former
  PR-specific browser skip is removed.
- **Development dependency security.** Update filelock to 4.2.4 in the reviewed
  development dependency set.

## Compatibility

Existing accounts, profiles, queue state, subscriptions, media mounts and Stable
release history are preserved. Announcements add a local SQLite store without
replacing the existing configuration. No deliberate breaking API change is
introduced.

## Known limitations

Official announcement delivery requires a correctly provisioned publisher; this
release does not configure or deploy the private signing key. The feed uses HTTPS
and Ed25519 signatures, not end-to-end content encryption. The local announcement
database is not encrypted at rest. Receipt/read counts use pseudonymous
installation and profile identifiers and are best-effort client self-reports,
not tamper-proof audience measurements. See [announcement operations](../ANNOUNCEMENTS.md).

Provider and NAS availability remain outside RoyalDownloader's control. The
bounded resource and recovery behavior from v2.0.1 remains in place.

## Upgrade

Back up `.env`, `data/`, `runtime/`, the running image/source revision and media
configuration. Use the guarded Stable update flow or a version-pinned checkout:

```bash
git fetch --tags origin
git switch --detach v2.0.2
APP_COMMIT_SHA="$(git rev-parse HEAD)" docker compose up -d --build
curl --fail http://127.0.0.1:8765/api/health
```

Verify application version `2.0.2`, queue recovery, subscriptions, both media
mounts and the Abo-Inbox. Configure global publishing only on the official
server, following the documented owner/key requirements; ordinary installations
do not need publisher environment variables.

## Rollback

Use the built-in versioned runtime rollback or restore the previous known-good
source tag with compatible persistent state. Keep `data/` and `runtime/`, including
the announcement database. See [release operations](../RELEASE.md#rollback).

## Release verification

The promotion/release PR must pass the protected branch checks before merging.
The existing release workflow repeats Quality on the Stable merge commit before
creating the annotated `v2.0.2` tag and publishing the GitHub Release.
