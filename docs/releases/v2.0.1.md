# RoyalDownloader v2.0.1

RoyalDownloader v2.0.1 promotes the current Stable `main` snapshot after the
Overnight merge. It combines Royal Discovery 3.0 with the subsequent fixes for
series loading, scrolling, Jellyfin ownership indicators, storage availability
and NAS resource usage.

## Highlights

- **Personal discovery.** Profile-specific Home recommendations use existing
  taste signals and bounded TMDB discovery, including actor/director, collection
  and related-title matches. Rejected preferences and actual visible exposure
  inform ranking. Landscape Spotlight cards and direct content-detail navigation
  restore the expected browsing behavior.
- **Reliable series browsing.** Season loading reuses cached results and shared
  bounded background work. Infinite scrolling, source selection and recovery
  deadlines address regressions introduced during Discovery 3.0 development.
- **Jellyfin and storage fixes.** Movie ownership ribbons survive navigation and
  background checks. Storage targets report availability and explicit mount
  confirmation consistently.
- **Bounded NAS work.** Dedicated storage workers, shared short-lived telemetry,
  bounded optional inference and caches, and bounded WebSocket ingress reduce
  resource accumulation. Unchanged inventory snapshots skip unnecessary writes.
- **Startup recovery and faster stylesheet delivery.** Failed module imports
  show a manual retry screen instead of an endless loader. The existing CSS
  cascade is combined into one gzip-capable response, avoiding 44 import requests
  without changing its visible presentation.
- **Guarded movie replacement.** An administrator-only API verifies the matching
  movie and replacement source before the explicit delete-and-download flow.
  Normal duplicate protection remains in place.
- **Dependency security.** Update certifi to 2026.10.19 to resolve the dependency
  audit finding.

## Compatibility

Existing accounts, profiles, queues, subscriptions, source/language settings,
Jellyfin configuration and persistent data formats are retained. The release
uses the current `main` content; the newer subscribed-series poster redesign in
PR #557 remains on Overnight and is not part of v2.0.1.

## Known limitations

External providers and their availability are outside RoyalDownloader's control.
Python cannot interrupt a kernel-blocked NAS filesystem call. Resource limits
prevent additional work from accumulating but cannot repair an unavailable mount,
NAS kernel or container manager. Optional AI refinement remains optional; busy
requests immediately use the normal baseline recommendations.

## Upgrade

Back up `.env`, `data/`, `runtime/`, the running image/source revision and the
media-library configuration. Use the existing guarded Stable update flow or a
version-pinned source checkout:

```bash
git fetch --tags origin
git switch --detach v2.0.1
APP_COMMIT_SHA="$(git rev-parse HEAD)" docker compose up -d --build
curl --fail http://127.0.0.1:8765/api/health
```

Verify application version `2.0.1`, queue recovery, subscriptions, Jellyfin
mappings and both media mounts after startup. Keep the backup until the update
has been validated on the NAS.

## Rollback

Use the built-in versioned runtime rollback or restore the previous known-good
source tag and compatible persistent state. Keep `data/` and `runtime/`.
See [release operations](../RELEASE.md#rollback).

## Release verification

The protected `main` branch requires the `verify` Quality check. The release
workflow repeats Quality before creating the annotated `v2.0.1` tag and official
GitHub Release. Chromium, WebKit, performance, backend and security checks cover
the promoted changes.
