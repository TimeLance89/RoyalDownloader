# RoyalDownloader v1.6.0

Stable v1.6.0 is a provider-coverage and stream-resolution release built from
the tested Stable promotion on 4 October 2026. It significantly broadens
RoyalDownloader's English movie/TV coverage while also strengthening the German
fallback pool and the direct-stream pipeline.

## Highlights

- **English movie and TV coverage expands substantially.** Stable now includes
  VidSrc, VidRift, VixSrc, VidRock, VidLink and MovieBox/AoneRoom as provider
  families alongside the existing English-capable sources.
- **German fallback coverage grows too.** FlixiTV, KinoKing, Movie2k, the
  HDFilme mirror family and KellerKino add more independent catalog and hoster
  paths.
- **Series resolution stays episode-exact.** New providers preserve explicit
  season/episode identity and the HDFilme family now survives failed mirrors,
  stale cached paths and relative detail URLs without falling back to the wrong
  episode.
- **Direct streams carry their real delivery requirements.** Provider results
  can preserve stream type, audio language, Referer, Origin, cookies and other
  required headers through probing and the final download.
- **HLS, MP4 and DASH/MPD are first-class paths.** MovieBox signed-cookie
  delivery and VidLink browser-captured streams are passed into the shared
  downloader rather than being isolated provider hacks.
- **VidSrc execution is bounded.** Provider-supplied WASM runs only from the
  known domains with size, import, fuel and memory limits; traps or malformed
  output become a clean provider miss.
- **VidSrc TV is more tolerant of transient upstream gaps.** One bounded retry
  with a short backoff is allowed before normal mirror/provider fallback.
- **Catalog browser stability improves.** The mobile browser regression waits
  for the rerendered catalog after genre changes and retries only the known
  detached-DOM scroll race.

## Quality and security

The promoted application state passed RoyalDownloader's full Stable quality
workflow before this release: Chromium and WebKit browser regressions, mobile
interaction checks, frontend performance budgets, dependency/security audits,
container build and high/critical vulnerability scanning, end-to-end
first-run/auth/queue/provider flows, and upgrade/rollback recovery.

The Stable promotion passed **1,271 Python tests**. The VidSrc hardening suite
explicitly covers an infinite WASM decrypt loop, excessive WASM memory and a
transient empty TV response.

## Compatibility

This is an additive minor release. Existing accounts, household profiles,
sessions, Jellyfin mappings, queues, subscriptions, provider preferences, media
paths, Storage Autopilot policy and personal request history remain compatible.

Existing provider priority/enabled selections are migrated additively so the new
provider families are registered once without duplicating saved entries.
KellerKino remains movie-only.

## Upgrade

Back up at least `.env`, `data/` and `runtime/`, then update to `v1.6.0`
through the normal Stable updater or a pinned checkout.

After startup:

1. verify **Settings → Updates and maintenance** reports v1.6.0;
2. open **Settings → Sources** and confirm the additional provider families are
   present;
3. test one movie and one series episode in the languages you normally use;
4. confirm existing queue, Jellyfin mappings and storage paths are unchanged.

## Rollback

Use the normal Stable rollback flow. Royal keeps the previous complete runtime
release and the release gate verifies upgrade, restart, rollback and backup
recovery against published Stable data.

If rolling back to v1.5.1, keep the normal `data/` and `runtime/` backup
available. The persistent formats remain compatible, but v1.5.1 does not know
the provider families and direct-stream metadata added in v1.6.0.

## Known limitations

- Third-party providers, mirrors and hosters can change availability, domains,
  protection or page structure independently of RoyalDownloader.
- VidRift has real title gaps; absence there is treated as a provider miss and
  normal fallback continues.
- VidSrc TV can still be intermittently unavailable upstream; v1.6.0 performs
  only one bounded retry to avoid request storms.
- VidFast is intentionally not enabled in this release because a reliable
  self-contained direct-stream resolution path was not verified.
- Some providers expose DASH/MPD while others expose HLS or MP4; the exact
  available quality and audio tracks remain source-dependent.
