# RoyalDownloader v1.3.0

## Source Sentinel

RoyalDownloader now promotes the Source Sentinel from Overnight to Stable. Enabled
providers are checked with bounded staged diagnostics, and hosters have their own
health evidence, runtime ranking and conservative declarative repair lifecycle.
Validated repairs require independent canaries, shadow validation, identity
preservation and rollback safeguards. CAPTCHA, Turnstile, login walls, rate
limits and unsupported protocols remain explicit boundaries rather than targets
for automated bypass.

The normal Settings view now leads with user impact instead of raw technical
diagnostics. Working alternatives can keep downloads available even when a
single provider or hoster is degraded. Browser-assisted production resolvers are
not marked broken merely because an HTTP-only probe cannot reproduce the browser
fallback path. Incomplete Sentinel diagnostics also no longer quarantine an
otherwise usable provider from production routing.

## Multi-language provider model

Provider capability, title availability and concrete episode tracks are now
separate concepts. AniWorld can participate in both German and English anime
paths while keeping German dub, German subtitles and English tracks distinct at
title/episode level. MKissa remains the global English provider, while explicitly
selected Japanese raw tracks are labelled and persisted correctly.

Setup, provider priorities, source selection and service-health evaluation now
use language-set intersection instead of assuming that one provider equals one
language. Existing configuration and queued download language values remain
compatible.

## Royal Storage Autopilot

The existing storage manager now includes optional Monitor, Advisor, Automatic
and Full modes for multi-volume installations. Volumes can be assigned Primary,
Overflow, Archive or Monitor roles, with explainable placement, utilization
thresholds, physical-volume reserves, series affinity and bounded persistent
inventory.

Automatic balancing uses the existing serial, verified and restart-safe move
runtime. Active queue work, uncertain ownership, changed mounts, collisions,
insufficient reserves and unreliable playback evidence block unsafe moves.
Automatic media deletion is not enabled by this release; cleanup remains a
separate preview-and-confirm action and excludes media, foreign files, backups,
symlinks and active staging work.

Cross-volume staging keeps the destination reservation for the eventual
publication copy. Before publication Royal checks the exact validated file size;
same-volume atomic publication does not reserve duplicate space.

## Reliability and interface

- Stabilize Source Sentinel disclosures and actions across Chromium and WebKit
  while background polling is active.
- Keep action feedback and unchanged controls stable during overlapping refreshes.
- Preserve provider/hoster diagnostics, repair history and administrator-only
  controls behind progressive disclosure.
- Add desktop, 390/430 px touch, WebKit, performance, security, container,
  persistence, E2E and upgrade/rollback regressions for the promoted features.

## Compatibility

No manual persistent-data migration is required. Existing provider selections,
content-language settings, queue jobs, sessions, subscriptions and media paths
remain compatible.

Hoster canaries used for active Sentinel probing remain intentionally ephemeral
across process restarts; runtime and diagnostic evidence stay bounded and
persistent. Royal relearns replayable hoster references from normal use after a
restart.

External providers can still change availability, markup, domains and protection
mechanisms without notice. Sentinel reduces the operational impact but cannot
guarantee third-party availability.

## Upgrade

Back up at least `.env`, `data/` and `runtime/`, then use the Stable updater
or check out `v1.3.0` and rebuild with the existing Compose mounts. Verify
`application_version: 1.3.0` in `/api/v1/capabilities`.

For multi-volume Storage Autopilot, begin with Monitor or Advisor mode and review
the detected volume identities, roles, reserves and recommendations before
enabling automatic moves.

See [release operations](../RELEASE.md), [Source Sentinel](../PROVIDER_SENTINEL.md)
and [Storage Autopilot](../STORAGE_AUTOPILOT.md).

## Rollback

Use Royal's runtime rollback or rebuild the previously recorded Stable tag while
keeping the same persistent volumes. If a rollback requires restoring application
state, restore `data/` and `runtime/` from the same backup set.
