# RoyalDownloader v2.0.4

RoyalDownloader v2.0.4 adds Royal Charts 3.0, expands film discovery and improves source recovery and NAS download publication.

## Highlights

- **Royal Charts 3.0.** Switch between Today, This Week and Breakouts on Home. Explore the Top 30 with film, series and genre filters, 7- and 30-day history and a breakdown of the ranking signals.
- **Film Worlds.** Browse studio and franchise collections, use the expanded filters and discover a more complete Disney Classics catalog.
- **Series and subscriptions.** Refresh stale source information, retry expired SerienStream cooldowns and use SerienStream as a fallback for missing episodes. Confirmed Filmpalast releases can be selected even when TMDB dates are out of sync. Movie subscriptions can acquire missing titles outside upgrade-only windows.
- **Jellyfin.** Share concurrent inventory reads by server, configuration and user to reduce redundant requests while preserving access and freshness checks.
- **NAS and container.** Preserve inherited UGREEN UGOS ACLs when publishing completed media. The container upgrades and checks the Debian APT packages.
- **Seasonal Home.** Optional Halloween effects follow the event calendar and can be switched off in settings.

## Compatibility

Existing accounts, settings, queues, subscriptions and media mounts use the same application data directory. The existing Daily Top endpoints remain available. The new `/api/v3/royal-charts` endpoint exposes the versioned chart data.

Royal Charts creates `royal_charts.sqlite3` alongside the application settings. Include it when backing up the persistent data directory. The [Royal Charts guide](../ROYAL_CHARTS.md) documents retention and signal handling.

## Known limitations

Chart history begins with the first successful collection. The chart day starts at 00:00 UTC. A missing or incomparable source measurement can leave historical modes or movement badges empty. The UGREEN fix applies when Royal publishes new files. Applying image-level APT updates requires rebuilding and recreating the container.

## Upgrade

Back up `.env`, `data/`, `runtime/` and the current revision before updating. Keep existing mounts and authentication keys.

```bash
git fetch --tags origin
git status --short
git switch --detach v2.0.4
docker compose config --quiet
APP_COMMIT_SHA="$(git rev-parse HEAD)" docker compose up -d --build
curl --fail http://127.0.0.1:8765/api/health
```

Check that the capabilities endpoint reports version `2.0.4` and that existing accounts, subscriptions, queues and both media mounts are accessible.

## Rollback

Use the guarded rollback or rebuild the known-good `v2.0.3` revision with its compatible state backup. Keep the current backup, media volumes and authentication keys. See [rollback operations](../RELEASE.md#rollback).
