# RoyalDownloader v1.4.0

Stable v1.4.0 promotes the tested household-profile improvements from Overnight
on top of the v1.3.1 Storage Autopilot hotfix line.

## Highlights

- Every RoyalDownloader household profile can link its own Jellyfin user.
  Playback history, favorites and ratings feed only that profile's Royal
  Intelligence model; Jellyfin server configuration and the media library remain
  shared.
- **Wer schaut gerade? → ⚙** is the central profile editor for display name,
  avatar and personal Jellyfin assignment.
- Eight bundled streaming-style character avatars are available locally, with
  initials as a fallback.
- Administrators can upload and manage additional household profile images from
  account settings. These images are stored locally and become selectable by the
  household profiles.
- The Abo-Inbox top-bar badge now signals items that need attention rather than
  counting passive or informational entries.

## Compatibility

This release is additive. Existing accounts, passwords, sessions, queues,
subscriptions, media paths, provider settings, Storage Autopilot configuration
and taste profiles remain compatible. Existing profiles without an avatar
continue to use their initials.

The Jellyfin server URL and API key remain instance-wide. A migrated legacy
administrator can continue using the previously configured global Jellyfin user
until an explicit personal link is saved.

## Upgrade

Back up at least `.env`, `data/` and `runtime/`, then update to `v1.4.0`
using the normal Stable updater or a pinned checkout. After the first start,
open **Wer schaut gerade? → ⚙** for each household profile and confirm the
intended Jellyfin user where personal playback learning is wanted.

Administrators can add further profile images under the account settings.

## Rollback

Use the normal Stable rollback procedure and keep the same persistent data
backup available. Older versions do not expose the new profile-avatar management
UI; custom avatar files may remain on disk unused until v1.4.0 or newer is
restored.

## Known limitations

- Profile images are household presentation assets; they are not synchronized
  back into Jellyfin user artwork.
- Jellyfin learning requires the linked Jellyfin account to be reachable through
  the configured instance-wide Jellyfin connection.
- Removing an administrator-uploaded avatar can make profiles that selected it
  fall back to their initials until another avatar is chosen.
