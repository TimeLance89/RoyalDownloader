# RoyalDownloader v1.5.1

Stable v1.5.1 is a reliability and completeness release built from the tested
Overnight state on 2 October 2026. It focuses on large real-world queues,
accurate storage planning and preventing temporarily unavailable episodes from
silently disappearing from the download plan.

## Highlights

- **Large Jellyfin libraries no longer block queue growth prematurely.** Ownership
  scans receive enough time to traverse established multi-page libraries, with
  regression coverage beyond the 550th pending job.
- **Storage Autopilot scales to very large queues.** Pending work uses bounded
  forecasting instead of multiplying every unknown item by a fixed 8 GiB, the old
  512-reservation ceiling is gone, and physical versus projected utilization is
  shown separately.
- **The 650-job stress case is covered explicitly.** The storage suite includes a
  three-volume scenario with about 18 TiB total capacity, about 12.7 TiB free,
  mixed known/unknown sizes and roughly 190 GiB already downloaded.
- **Episode downloads are completeness-first.** Temporary source/hoster failures
  remain active, retry with exponential backoff and then enter a low-frequency
  24-hour long-term check instead of becoming silent permanent misses.
- **Existing pre-fix gaps are recovered.** Retained source failures are
  reactivated on upgrade, and older intentional episode requests that have
  already fallen out of the 500-row terminal queue history can be reconstructed
  once from durable personal request intent.
- **Waiting work is understandable.** The download plan distinguishes source
  waits from provider cooldowns and shows the next retry, provider test or
  long-term check on desktop and narrow mobile layouts.

## Quality and security

The promoted Stable state passed RoyalDownloader's full quality workflow:
Chromium and WebKit browser regressions, mobile interaction checks, frontend
performance budgets, dependency and security audits, container build and
high/critical vulnerability scanning, end-to-end first-run/auth/queue/provider
flows, and upgrade/rollback recovery.

The Stable promotion immediately before this release passed **1,193 Python
tests** with 57% monitored overall coverage. The critical coverage gates remained
at 75% to 95% depending on the protected module.

## Compatibility

This is an additive patch release. Existing accounts, household profiles,
sessions, Jellyfin mappings, queues, subscriptions, provider settings, media
paths, Storage Autopilot policy and personal request history remain compatible.

Temporary episode source failures now stay active longer by design. Explicit
user cancellations remain terminal. Storage failures and other non-source
terminal errors are not reclassified as source waits.

## Upgrade

Back up at least `.env`, `data/` and `runtime/`, then update to `v1.5.1`
through the normal Stable updater or a pinned checkout. After startup:

1. verify **Settings → Updates and maintenance** reports v1.5.1;
2. open the download plan and confirm source-waiting episodes show their retry
   reason and next check;
3. if upgrading from v1.5.0 with earlier failed episode downloads, allow the
   startup recovery pass to reconcile retained source failures;
4. review **Storage** during a large queue and confirm physical and projected
   utilization are shown separately.

## Rollback

Use the normal Stable rollback flow. Royal keeps the previous versioned runtime
release and the release gate verifies upgrade, restart, rollback and backup
recovery against published Stable data.

If rolling back while v1.5.1 has source-waiting jobs, keep the normal `data/`
and `runtime/` backup available. The queue document remains backwards
compatible, but older code does not implement the new long-term source retry
semantics.

## Known limitations

- Third-party providers, mirrors and hosters can change availability, protection
  or page structure independently of RoyalDownloader.
- Long-term source gaps are deliberately rechecked only once per 24 hours after
  the faster retry phase to avoid hammering providers.
- Recovery beyond the bounded 500-row terminal queue history relies on durable
  intentional personal-request records; unrelated historical failures are not
  guessed or resurrected.
- Movies retain their existing terminal source-failure behavior in this patch;
  the completeness-first long-term retry path is scoped to series/anime episodes.
