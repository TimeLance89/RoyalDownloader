# RoyalDownloader v1.2.2

## Similar titles keep their complete details

Opening a similar movie now keeps the recommendation's existing metadata and
starts TMDB, Jellyfin and provider work independently. Provider failures no longer
replace rich metadata with sparse payloads, and late metadata cannot remove
already resolved hosters. Virtual TMDB selections receive library badge updates
even when they are absent from the currently displayed catalog.

Each selection owns its requests. Changing titles or closing the dialog aborts
old work; generation checks also reject responses from transports that complete
late. A failed title does not pass its availability error to the next title.
Catalog background enrichment cannot reset a settled detail to loading.

Similar series retain their known details and can retrieve full TMDB metadata by
ID independently of the existing provider episode resolver. Provider failures
leave description, artwork and discovery cards usable.

## External availability

The normal UI shows **Anbieter derzeit nicht erreichbar** or **Derzeit nicht
verfügbar**, with technical causes retained in diagnostic logs. No hoster is a
normal availability result, not a reason to remove metadata.

Movie metadata has a 12-second browser deadline, provider requests 20 seconds,
and library checks 15 seconds. Interactive virtual-movie search waits up to four
seconds per canonical/original-title query and eight seconds for candidate
loading, returning completed providers in configured priority order. Worker
concurrency and queued jobs are bounded. Python cannot forcibly stop a running
scraper thread; those calls retain their own network timeouts. Closing/reopening
a failed movie retries availability while reusing loaded metadata.

## Regression coverage

New loader tests reproduce the previous blocking sequence and cover response
ordering and stale selections. Desktop and touch-mobile browser fixtures exercise
actual Similar cards, populated metadata, provider failure, unavailable/slow
Jellyfin, recovery on the next title, rapid navigation, empty hosters and series.
Backend tests cover partial provider results under deadlines and sanitized error
contracts. Existing catalog, architecture, CSS, browser, WebKit and performance
gates remain required.

## Compatibility

No CSS, carousel, image-quality, framework, deployment or persistent-data format
change is included. The v1.2.1 catalog and queue fixes remain intact.

## Upgrade

Back up `.env`, `data/` and `runtime/`, then use the Stable updater or check out
`v1.2.2` and rebuild with the existing Compose mounts. Verify
`application_version: 1.2.2` in `/api/v1/capabilities`. Open a movie, choose a
similar title and check its metadata and independent availability status.
See [release operations](https://github.com/TimeLance89/RoyalDownloader/blob/v1.2.2/docs/RELEASE.md).

## Rollback

Use the existing runtime rollback or rebuild the recorded previous tag with
unchanged volumes. No reset or data deletion is required. Returning to v1.2.1
restores the earlier similar-detail behavior.

## Known limitations

External providers and TMDB may still be unavailable. Tests verify Royal's
response to these failures; they cannot guarantee third-party uptime or source
availability for every title. Physical-device Safari testing remains useful
alongside the automated WebKit gate.
