# RoyalDownloader v1.2.1

## Critical catalog hotfix

Update from v1.2.0: movie and series catalog cards could remain empty while the
navigation, hero and filters appeared normally. The shared poster renderer used
`const coverCandidates = coverCandidates(...)`, shadowing its injected function
and throwing `Cannot access 'coverCandidates' before initialization`. The local
array now has a distinct name; both catalogs render their cards and posters again.

A scope-aware audit of all 166 frontend modules found one additional matching
issue in the Home card-dock queue action: a local `active` boolean hid the
lifecycle scope after an awaited operation. It now has a distinct queue-state
name, preserving cancellation ownership and successful button/status updates.
No further matching immediate-use TDZ cases were found.

## Regression coverage

- Two targeted tests inject the artwork-candidate dependency and assert actual
  poster creation, candidate forwarding and lazy/async properties. Both failed
  with the exact original ReferenceError before the renderer fix.
- An additional Home dock test exercises add/remove completion; it failed before
  the second fix instead of silently accepting the caught error state.
- A required browser gate supplies populated catalogs, checks real movie and
  series result cards and decoded posters, metadata/Jellyfin badges, details,
  filters, sorting, genre selection and second-page loading. Smartphone contexts
  exercise native card taps and vertical panning without accidental detail opens.
- Unhandled page errors and unexpected console errors fail the gate. The existing
  intentional 503 fixture allowance is restricted to the exact network diagnostic.

## Compatibility

This patch changes two local JavaScript bindings and strengthens tests. It keeps
the existing design, card layout, ES-module architecture, lazy artwork, bounded
carousel clones, offscreen rendering and native touch/momentum handling.
There is no backend data-format or deployment change and no new application
dependency or build pipeline.

## Upgrade

Back up `.env`, `data/` and `runtime/`, then use the Stable updater or check out
`v1.2.1` and rebuild using the existing Compose configuration and volumes. Verify
`application_version: 1.2.1` in `/api/v1/capabilities`, open **Movies** and
**Series**, and confirm populated cards, posters and details. Restart once and
check your existing queue, subscriptions and account data.

[Release operations](https://github.com/TimeLance89/RoyalDownloader/blob/v1.2.1/docs/RELEASE.md)
contains installation, backup and runtime rollback commands.

## Rollback

The existing runtime rollback or a rebuild of the recorded previous tag with
unchanged volumes remains available. Returning to v1.2.0 also restores its catalog
rendering defect, so prefer v1.2.1 for normal operation. Restore a matching backup
only if needed; no settings reset or data deletion is part of this upgrade.

## Known limitations

Provider availability remains external. Browser fixtures verify Royal's rendering
and interaction contracts, not availability of every live provider. Existing
WebKit coverage does not replace physical iPhone/Safari momentum testing.
