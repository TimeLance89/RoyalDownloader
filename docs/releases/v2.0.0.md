# RoyalDownloader v2.0.0

RoyalDownloader v2.0.0 marks a major Stable milestone: the accumulated
Overnight improvements since v1.9.0 are brought together into a more mature
release for download reliability, responsive browsing, Jellyfin catalogs,
mobile navigation and safer Docker upgrades. Version 2.0.0 is a product
milestone, not a deliberate breaking API or persistent-data migration.

## Highlights

- **More responsive browsing.** Slow persistent stores, profile/authentication
  snapshots, WebSocket checks and selected Jellyfin lookups no longer block
  unrelated server requests. Shared checks, limited verification work and
  cancellable pending results reduce stalls on media-rich detail pages.
- **Restart-safe direct HTTP downloads.** Direct HTTP/MP4 transfers can resume
  from validated byte-range checkpoints after interruption or planned update.
  Strong validators and range/length checks refuse unsafe resumptions.
  This does not promise resuming every HLS or hoster stream.
- **Durable queue and worker recovery.** Queue snapshots keep a validated backup
  for recovery after incomplete writes or corrupt primary state. Scheduling,
  provider retries, subscriptions, Seerr polling and Telegram handlers recover
  more safely from temporary failures without dropping accepted work.
- **Safer Docker updates.** An independent startup guard verifies health and
  the exact running revision and can restore the previous known-good runtime
  after a failed activation. This requires a rebuilt Docker image.
- **Mobile Download Center 2.0.** A redesigned mobile queue experience uses
  focused-title artwork, clear progress and provider feedback, accessible
  controls and expandable history. Navigation, search and subscription inbox
  access are improved.
- **Series and Jellyfin polish.** More complete series catalogs, resilient
  pagination/prefetch, static Jellyfin ownership ribbons and synchronized
  episode-inventory status. Trailer playback preserves the active player
  rather than restarting a duplicate.
- **Provider and discovery reliability.** Collection availability waits for
  confirmed results instead of marking temporary provider failures as absent;
  home recommendations prefer suitable landscape TMDB artwork.
- **Verification.** Expanded browser, WebKit, mobile, queue-stress,
  persistence, offline-isolation and performance regression coverage.

## Compatibility

Existing accounts, profiles, queues, subscriptions, source/language choices,
Jellyfin settings, persistent storage and media mounts remain intended to be
compatible.

## Known limitations

External providers, their language metadata and service
availability are not under RoyalDownloader's control. A subtitle release is
not proof of a matching audio track. The startup guard protects only runtime
layouts where its independent Docker bootstrap has been installed.

## Upgrade

Back up at least `.env`, `data/`, `runtime/`, running image/source revision
and the media-library configuration before updating. Review the update
comparison in **Settings → Updates and Wartung**, select the Stable channel
and use the existing guarded update process. From a source checkout:

```bash
git fetch --tags origin
git switch --detach v2.0.0
APP_COMMIT_SHA="$(git rev-parse HEAD)" docker compose up -d --build
curl --fail http://127.0.0.1:8765/api/health
```

Verify version `2.0.0`, queue and subscriptions, existing Jellyfin
mappings, media mounts and read/write permissions after startup. Keep the
backups until the update has been validated on the NAS.

## Rollback

Use the built-in versioned runtime rollback or restore a known-good source
tag and compatible persistent state. Do not remove `data/` or `runtime/`.
See [release operations](../RELEASE.md#rollback).

## Release verification

Both protected branches require passing `verify` checks. On promotion
to `main`, the release workflow repeats Quality, creates the annotated
`v2.0.0` tag and publishes the official GitHub Release with these notes
only after those checks succeed.
