# RoyalDownloader v1.0.0 Stable

RoyalDownloader 1.0.0 is the first Stable release of the self-hosted discovery,
automation, and download service for movies, series, and anime. It promotes the
reviewed RC3 data format and the subsequent Overnight hardening work without
changing the established Stable (`main`) and Overnight (`overnight`) channels.

## Highlights

- Discover movies, series, and anime through configurable language-aware
  providers, TMDB metadata, global search, recommendations, Mood Mode, and a
  daily Top 10.
- Use persistent logical download jobs with stable IDs, isolated attempts,
  progress/history, provider and hoster fallbacks, cancellation/retry controls,
  atomic snapshots, duplicate prevention, and restart recovery.
- Match against Jellyfin before queueing, refresh libraries after completed
  downloads, track playback and existing episodes, schedule quality upgrades,
  and maintain recommendation collections.
- Accept movie and series requests through Telegram and approved Seerr
  requests. When the Moonfin plugin is installed, Royal can configure its
  Jellyfin dashboard and Seerr area; Radarr and Sonarr are not required for this
  route.
- Run subscriptions and unattended automation with weekday/weekend windows,
  bounded parallelism and bandwidth, free-space protection, and optional
  Jellyfin playback throttling.
- Monitor multiple storage locations and perform guarded, restart-safe media
  moves without overwriting an existing destination or deleting a source before
  verification.

## Security and runtime hardening

- Authentication is fail-closed. `APP_REQUIRE_AUTH=false` is retained only for
  compatibility with older environment files and does not expose protected
  routes without an account.
- First-run ownership requires the one-time bootstrap token; the token file is
  created with restrictive permissions and is consumed after setup.
- Web sessions and Mobile/Bearer authentication remain separate. A web session
  can use protected web routes but is rejected by bearer-only `/api/v1` routes.
- The production container runs as the unprivileged `royal` user (UID/GID 1000
  by default), drops all Linux capabilities, enables `no-new-privileges`, and
  supports a read-only root filesystem with explicit persistent mounts and
  bounded tmpfs locations.
- Chromium verification and shared SerienStream sessions use isolated browser
  processes and profiles with validated CDP and provider URL boundaries.
- Runtime and development dependencies are locked and audited. Quality also
  performs Bandit, the project security regression scan, CodeQL, Trivy
  HIGH/CRITICAL scanning, and dependency/container SBOM generation.
- The in-app updater verifies exact Stable/Overnight revisions, stages complete
  releases in isolation, activates atomically, and retains a previous release
  for rollback.

## Upgrade from v1.0.0-rc.3

1. Stop or drain active downloads and back up `.env`, `data/`, and `runtime/`.
   Do not copy Seerr's SQLite files while Seerr is running.
2. Fetch tags, check that the source checkout has no unreviewed local changes,
   and switch to `v1.0.0`.
3. Rebuild/restart the container while preserving the same data, runtime, movie,
   series, and Seerr volumes.
4. Verify `/api/health`, `/api/v1/capabilities`, the displayed build SHA,
   authentication, queue state, integrations, and media paths. Restart once and
   verify the same state again.

The release gate creates realistic RC3 settings, authentication and queue data,
starts 1.0.0 twice on the same persistent state, returns to the RC3 code for a
rollback read, restores a separate volume from backup, and verifies the restored
state with RC3 again.

See the complete [release operations guide](../RELEASE.md) and
[Docker/NAS guide](../DOCKER.md).

## Rollback and recovery

- Source rollback: stop the stack, switch to the backed-up commit/tag, rebuild,
  and keep persistent volumes unchanged.
- Runtime rollback: use **Settings → Updates → Rollback** or invoke
  `docker_bootstrap.py --rollback` in the Compose service.
- Full recovery: stop all writers and restore the backed-up `data/` and
  `runtime/` together before restarting. Restore Seerr data only from a
  consistent stopped-container backup.
- After any rollback or restore, verify liveness, application version/build,
  login, queue identity/count, subscriptions, integrations, and both media
  mounts before resuming automation.

## Compatibility and breaking changes

There is no intentional breaking API or persistent-data change from RC3.
Existing slug-based routes, additive `/api/v1` aliases, WebSocket event names,
Docker mount points, queue correlation keys, and Stable/Overnight channel
semantics remain supported. New automation fields are additive and retain the
values stored by RC3.

Security behavior is stricter than historical pre-RC installations: protected
operation without an administrator account is no longer supported, even when an
old `.env` contains `APP_REQUIRE_AUTH=false`. Such installations must complete
the protected setup migration.

## Known non-release-critical limitations

- Third-party providers can change domains, markup, availability, geoblocking,
  rate limits, or interactive protection independently of RoyalDownloader.
- A valid TMDB API key or read token is required to complete a new setup.
- 4K Seerr requests remain unsupported unless a provider offers an explicit,
  guaranteed 4K selection; they are not silently downgraded.
- Moonfin dashboard integration is optional and is skipped when the compatible
  Jellyfin plugin is not installed.
- Provider availability is not guaranteed; configured fallback and cooldown
  behavior limits failures but cannot remove external dependencies.
