# RoyalDownloader v1.3.1

## Critical fix

v1.3.1 fixes a Storage Autopilot regression introduced in v1.3.0 that could
prevent downloads from starting in **Automatic** or **Full** mode.

Royal's physical download scheduler also contains internal preparation jobs.
Those preparation workers intentionally do not have media-download fields such
as `job_id`, `out_path` or byte counters. The new storage reservation snapshot
mistakenly treated them like real downloads and could abort preparation with:

`'_QueuePreparationJob' object has no attribute 'job_id'`

The storage runtime now ignores internal preparation jobs and records only real
physical media downloads in supplemental reservation accounting. Attribute
access is also defensive so scheduler helper objects cannot crash placement.

A dedicated regression test covers the production shape: one active internal
preparation worker plus one real pending movie download.

## Compatibility

No persistent-data migration or configuration reset is required. Existing
Storage Autopilot policies, reservations, inventory, queue history, providers,
sessions and media paths remain compatible.

The fix does not change destination scoring, Primary/Overflow/Archive behavior,
series affinity, minimum reserves, move safety or cleanup permissions.

## Upgrade

Users on v1.3.0 should update to v1.3.1, especially when using **Automatic** or
**Full** Storage Autopilot modes. Rebuild/restart through the normal Stable
updater or check out `v1.3.1` using the existing persistent Docker mounts.

After startup, retry the previously blocked download. No storage policy needs to
be recreated.

## Rollback

If required, stop Royal and return to the previously recorded Stable source or
runtime release while keeping the same persistent `data/`, `runtime/` and media
mounts. No v1.3.1-specific state migration needs to be reversed.

## Known limitations

Storage Autopilot remains conservative by design: it does not mount host disks,
does not automatically delete media, and autonomous moves still require current
ownership, capacity, queue and playback safety checks. External source/provider
availability is independent of this hotfix.
